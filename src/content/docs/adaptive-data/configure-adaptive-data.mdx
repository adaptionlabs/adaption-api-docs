After you [map your columns](/adaptive-data/select-columns), configure how Adaptive Data transforms them. You can expand the dataset, choose its training format, apply recipes, limit the run, and define output requirements.

The SDK examples below assume you have [configured the Python SDK](/introduction/getting-started) and set `ADAPTION_DATASET_ID` to an [imported dataset](/adaptive-data/create-a-dataset):

```python
import os

from adaption import Adaption

client = Adaption()
dataset_id = os.environ["ADAPTION_DATASET_ID"]
column_mapping = {
    "prompt": "instruction",
    "completion": "response",
}
```

## Expand across languages and locales

Language expansion adds rows in other languages or locales. Two methods run a one-off expansion on an existing dataset. Each one writes a **new** dataset that holds the source rows plus the added rows, and leaves the source dataset unchanged:

- **[`datasets.translate`](/api/python/resources/datasets/methods/translate)** converts a sample of rows into other languages. Adaptive Data supports up to 242 languages.
- **[`datasets.localize`](/api/python/resources/datasets/methods/localize)** adapts a sample of rows for a country and language pair, including locale-specific wording rather than direct translation alone.

Both methods take `sample_rate`, the fraction of source rows expanded for each target. With two targets and a `0.25` sample rate, the new dataset holds approximately `1 + (0.25 × 2) = 1.5` times as many rows as the source. Expansion is billed on the rows it adds. Pass `estimate=True` to receive a credit quote without starting a run or creating a dataset.

### Translate rows

Provide [ISO 639-1 language codes](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes) in `languages`:

```python
estimate = client.datasets.translate(
    dataset_id,
    sample_rate=0.25,
    languages=["es", "fr"],
    estimate=True,
)
print(f"Estimated credits: {estimate.estimated_credits_consumed}")

translation = client.datasets.translate(
    dataset_id,
    sample_rate=0.25,
    languages=["es", "fr"],
)
print(f"New dataset: {translation.dataset_id}")
```

### Localize rows

Provide country/language pairs in `pairs`, using [ISO 3166-1 alpha-2 country codes](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2#Officially_assigned_code_elements) and [ISO 639-1 language codes](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes):

```python
localization = client.datasets.localize(
    dataset_id,
    sample_rate=0.25,
    pairs=[
        {"country": "CA", "language": "fr"},
        {"country": "MX", "language": "es"},
    ],
)
print(f"New dataset: {localization.dataset_id}")
```

Each pair creates a country- and language-specific variant rather than only translating the text. Unsupported language codes or pairs return a `400` response with a sample of the supported values.

### Wait for the new dataset

Both responses carry the `dataset_id` of the new dataset and its `status` at the time of the call. Both fields are `None` for an estimate, which creates nothing. Poll [`datasets.get_status`](/api/python/resources/datasets/methods/get_status) on the new ID until it reaches `succeeded`, or let `wait_for_completion` poll for you:

```python
expanded_id = translation.dataset_id
if expanded_id is None:
    raise RuntimeError("Estimate-only request created no dataset")

status = client.datasets.wait_for_completion(expanded_id, timeout=3600)
print(f"Status: {status.status}")
```

`wait_for_completion` returns when the status is `succeeded` or `failed` and raises `adaption.DatasetTimeout` after `timeout` seconds. The expansion keeps running on the server after a timeout, so call it again with the same ID to resume waiting. Once the status is `succeeded`, [download the new dataset](/api/python/resources/datasets/methods/download) or use it in a fine-tuning run.

<Callout variant="note">
  Pass `idempotency_key` when your application might retry the request. A
  second call with the same key returns the dataset the first call created
  instead of starting and charging for a second run.
</Callout>

### Expansion saved on the dataset

Expansion can also be a setting stored on the dataset. It is the same setting the app wizard shows for that dataset. Calling `datasets.run` with `language_expansion` updates the stored setting and launches an adaptation run with it. Omitting `language_expansion` launches with the stored setting unchanged, and passing `language_expansion=None` turns the setting off before the run:

```python
run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    language_expansion={
        "type": "translate",
        "sample_rate": 0.25,
        "languages": ["es", "fr"],
    },
)
print(f"Run started: {run.run_id}")
```

The `localize` form takes `"type": "localize"` and `pairs` instead of `languages`. Unlike `translate` and `localize`, this path expands rows inside the adaptation run of the same dataset and does not create a new one. See the [`datasets.run` reference](/api/python/resources/datasets/methods/run) for the current schema and supported values.

## Apply recipes

Recipes are optional transformations that operate on the mapped data:

- **Prompt deduplication** removes duplicate prompts to keep examples diverse.
- **Prompt rephrasing** rewrites prompts for clarity and alignment with the task.
- **Reasoning traces** add explicit intermediate reasoning to adapted completions.

In the SDK, recipes belong under `recipe_specification.recipes`. You can enable more than one recipe in the same run:

```python
run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    recipe_specification={
        "recipes": {
            "deduplication": True,
            "prompt_rephrase": True,
            "reasoning_traces": True,
        },
    },
)
print(f"Run started: {run.run_id}")
```

<Callout variant="note">
  The exact reasoning-trace output depends on the API and recipe version.
  Inspect the downloaded dataset and see `RecipeSpecification` on the
  [`datasets.run` reference](/api/python/resources/datasets/methods/run).
</Callout>

Use reasoning traces when auditability, distillation, or supervised reasoning data matters. Omit them when you need only short final answers and want to reduce token use.

## Generate preference pairs

By default, Adaptive Data produces an instruction dataset for supervised fine-tuning. Set `training_type` to `preference_pairs` when you instead need chosen and rejected responses for preference training such as DPO.

The source mapping stays the same: provide a `prompt` column and, optionally, an existing `completion` column. Adaptive Data generates the preference-pair fields in the output.

```python
preference_mapping = {
    "prompt": "instruction",
    "completion": "response",
}

estimate = client.datasets.run(
    dataset_id,
    column_mapping=preference_mapping,
    training_type="preference_pairs",
    estimate=True,
)
print(f"Estimated credits: {estimate.estimated_credits_consumed}")

run = client.datasets.run(
    dataset_id,
    column_mapping=preference_mapping,
    training_type="preference_pairs",
)
print(f"Run started: {run.run_id}")
```

Use `training_type="instruction_dataset"`—or omit `training_type`—to produce enhanced prompt/completion pairs instead. Language expansion, recipes, job limits, and brand controls can be included in the same preference-pair run. See `training_type` on the [`datasets.run` reference](/api/python/resources/datasets/methods/run) for the current schema.

## Limit rows and estimate a run

Use `job_specification.max_rows` to test mappings and controls on a subset before processing a large dataset. [Request an estimate with `datasets.run`](/api/python/resources/datasets/methods/run) first to validate the same configuration and receive a credit quote without starting adaptation:

```python
job_specification = {"max_rows": 500}

estimate = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    job_specification=job_specification,
    estimate=True,
)
print(f"Estimated credits: {estimate.estimated_credits_consumed}")

run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    job_specification=job_specification,
)
print(f"Run started: {run.run_id}")
```

Omit `max_rows` when you want to process the full dataset. See `JobSpecification` on the [`datasets.run` reference](/api/python/resources/datasets/methods/run) for all job-level options.

## Configure brand controls

`brand_controls` makes output requirements part of the adaptation run:

- **`length`** controls target verbosity: `minimal`, `concise`, `detailed`, or `extensive`.
- **`safety_categories`** identifies content-safety categories to enforce.
- **`hallucination_mitigation`** grounds generations with web search where applicable.
- **`blueprint`** supplies freeform instructions for tone, persona, audience, language, or product-specific wording.

### Reduce hallucinations

Hallucination mitigation steers generated completions toward verifiable information. Enable it for fact-sensitive data such as customer support, grounded question answering, or compliance workflows:

```python
run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    brand_controls={"hallucination_mitigation": True},
)
```

Grounding can affect latency and credit use. Use `estimate=True` to compare the run before scaling it.

### Control length and safety

Length and safety constraints compose in the same `brand_controls` object. Use the [`datasets.run` reference](/api/python/resources/datasets/methods/run) as the source of truth for supported safety category names:

```python
run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    brand_controls={
        "length": "concise",
        "safety_categories": ["harassment", "hate"],
    },
)
```

### Set a Blueprint

Use `blueprint` for qualitative requirements that do not fit a structured field. It acts as a system instruction for generated completions and applies consistently across the run:

```python
run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    brand_controls={
        "blueprint": (
            "You are a customer-success assistant for Acme. "
            "Answer in British English with a warm, direct tone. "
            "Do not recommend third-party tools."
        ),
    },
)
```

### Combine brand controls

Structured controls and Blueprint instructions can be used together:

```python
brand_controls = {
    "length": "concise",
    "safety_categories": ["harassment", "hate"],
    "hallucination_mitigation": True,
    "blueprint": "Answer in British English with a warm, direct tone.",
}

estimate = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    brand_controls=brand_controls,
    job_specification={"max_rows": 500},
    estimate=True,
)
print(f"Estimated credits: {estimate.estimated_credits_consumed}")

run = client.datasets.run(
    dataset_id,
    column_mapping=column_mapping,
    brand_controls=brand_controls,
    job_specification={"max_rows": 500},
)
print(f"Run started: {run.run_id}")
```

After the run completes, [evaluate dataset quality](/adaptive-data/evaluate-dataset-quality) and [download the adapted rows](/api/python/resources/datasets/methods/download).
