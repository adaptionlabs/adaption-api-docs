AutoScientist は学習の前に[完全な学習レシピを提案](/api/python/resources/autoscientist/methods/recommend_hyperparams)し、その後イテレーションを重ねながらレシピを評価・調整します。**ほとんどの実行では、推奨値をそのまま使ってください。** AutoScientist は、これらの値をまとめて選択し、測定結果に基づいて改善するよう最適化されています。

<Callout variant="warning">
  個々のハイパーパラメーターを変更することは推奨されません。上書きすると、AutoScientist が本来選択したはずの設定を探索できなくなり、学習の品質が低下することがあります。特定の実験上またはインフラ上の制約がある場合にのみ値を上書きしてください。
</Callout>

## ハイパーパラメーターのリファレンス

`training_method` は `create` のトップレベル引数です（`instruction` または `alignment`）。以下のその他のフィールドは、`hyperparams` の中のキーです。

### 全般的な学習

これらのハイパーパラメーターは、SFT と DPO の両方の実行に適用されます。

| ハイパーパラメーター     | 定義                                                                                                                                                                      | 有効な値                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `learning_rate`          | オプティマイザーのピーク学習率。重み更新時のステップ幅を制御します。                                                                                                      | `[1e-6, 5e-4]` の範囲の浮動小数点数                                        |
| `n_epochs`               | 学習がデータセット全体を通過する回数。                                                                                                                                    | 整数、`1`〜`5`                                                             |
| `batch_size`             | 学習ステップごとのサンプル数。SFT では `"max"` でなければなりません。DPO では 2 のべき乗の整数または `"max"`。                                                            | `"max"` または 2 のべき乗の整数 ≥ 1                                        |
| `lr_scheduler_type`      | 学習中に学習率がどう変化するか。linear のスケジュールは一定の割合で減衰し、cosine のスケジュールは終盤で減衰が緩やかになります。                                          | `"linear"` \| `"cosine"`                                                  |
| `min_lr_ratio`           | ピークに対する割合で表した学習率の下限。学習率は `learning_rate × min_lr_ratio` を下回りません。                                                                          | 浮動小数点数、`0.0`〜`1.0`                                                 |
| `scheduler_num_cycles`   | 学習全体でのコサイン減衰サイクルの数（小数可）。cosine のスケジュールにのみ影響します。                                                                                   | 浮動小数点数 `> 0.0`（既定値 `0.5`）                                       |
| `warmup_ratio`           | 学習率をゼロから徐々に引き上げるのに費やす、学習ステップ全体に対する割合。目標の学習率への移行を滑らかにします。                                                          | 浮動小数点数、`0.0`〜`1.0`（通常は `0.03`〜`0.1`）                         |
| `max_grad_norm`          | 勾配クリッピングの最大勾配ノルム。勾配の大きさに上限を設け、勾配爆発や不安定な更新を抑えます。無効にするには `0.0` を設定します。                                        | 浮動小数点数 ≥ `0.0`                                                       |
| `weight_decay`           | L2 正則化のペナルティ。重みが過度に大きくなるのを抑え、過学習の防止と未知データへの汎化に役立ちます。                                                                    | 浮動小数点数 ≥ `0.0`                                                       |
| `training_type`          | 学習戦略。`"lora"` は低ランクアダプターを挿入し、`"full"` はモデルの全重みを更新します。フルファインチューニングは[サポート対象モデル](/ja/autoscientist/supported-models)でのみ利用できます。 | `"lora"` \| `"full"`                                                       |

### LoRA

これらのハイパーパラメーターは Low-Rank Adaptation を設定するもので、`training_type` が `"lora"` の場合にのみ適用されます。アライメント（SFT → DPO）のパイプラインでは、LoRA の設定は勝者となった SFT イテレーションのものに固定され、DPO の間は変更できません。

| ハイパーパラメーター     | 定義                                                                                                                                                                      | 有効な値                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `lora_r`                 | LoRA アダプター行列のランク。アダプターの容量を制御します。ランクが高いほど複雑な適応を表現できますが、より多くのメモリと計算を必要とします。                            | 2 のべき乗の整数、`1`〜`64`                                                |
| `lora_alpha`             | ベースモデルに対する LoRA アダプターの寄与のスケーリング係数。`lora_r` の値の `1×` または `2×` でなければなりません。                                                    | 2 のべき乗の整数（`lora_r` の `1×` または `2×`）                          |
| `lora_dropout`           | 学習中に LoRA 層へ適用されるドロップアウト確率。過学習を抑えるための正則化を加えます。                                                                                   | 浮動小数点数、`0.0`〜`1.0`（通常は `0.0`〜`0.1`）                          |
| `lora_trainable_modules` | どのモデル層に LoRA アダプターを付与するか。`"all-linear"` はすべての線形層を対象にします。あるいは、モジュール名をカンマ区切りで指定します。                            | `"all-linear"` またはカンマ区切りのリスト（例: `"q_proj,v_proj,o_proj"`） |

### SFT 固有

| ハイパーパラメーター | 定義                                                                                                                                                                          | 有効な値           |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `train_on_inputs` | 学習損失をコンプリーションのトークンに加えてプロンプトのトークンでも計算するかどうか。`false` にするとプロンプトがマスクされ、モデルはコンプリーションの生成だけを学習します。 | `true` \| `false`  |

### アライメント固有

これらのハイパーパラメーターは、選好ベース（DPO）の学習にのみ適用されます。SFT の実行では無効です。

| ハイパーパラメーター                | 定義                                                                                                                                                                                                                                                                                                                                                                         | 有効な値                            |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `dpo_beta`                          | モデルが参照モデルからどれだけ離れてよいかを制御します。値が小さい（`0.1` 前後）ほど、選好された出力へ積極的に更新され、値が大きい（`0.7` 前後）ほど参照モデルの近くに留まります。                                                                                                                                                                                           | 浮動小数点数、`0.05`〜`0.9`         |
| `dpo_normalize_logratios_by_length` | 損失の計算時に、対数比をサンプル長で正規化します。`simpo_gamma` が `0` より大きい場合は自動的に `true` になります。このフラグを変えると `dpo_beta` の実効スケールが変わるため、変更は大きな介入として扱ってください。                                                                                                                                                       | `true` \| `false`                   |
| `rpo_alpha`                         | 標準的な DPO 損失に加えて、選好されたレスポンスに対する補助的な負の対数尤度（NLL）損失の重み（Regularized Preference Optimization）。報酬マージンが広がっても採用レスポンスの確率が下がってしまう「尤度のずれ（likelihood displacement）」という失敗モードを打ち消します。無効にするには `0.0` を設定します。**`simpo_gamma` とは併用できません。**                      | 浮動小数点数 ≥ `0.0`（通常 `0.1`〜`1.0`） |
| `simpo_gamma`                       | Simple Preference Optimization の目標報酬マージン。`0.0` より大きい場合、目的関数は参照不要かつ長さ正規化されたものになり、採用レスポンスは不採用レスポンスを少なくともこのマージンだけ上回る必要があります。SimPO は通常かなり大きなベータを必要とするため、`dpo_beta` も合わせて引き上げてください。無効にするには `0.0` を設定します。**`rpo_alpha` とは併用できません。** | 浮動小数点数 ≥ `0.0`（通常 `0.3`〜`1.6`） |

## アプリで確認する

提案されたフィールドは編集できますが、既定のワークフローは内容を確認して受け入れることです:

1. モデル、アルゴリズム、生成されたレシピを確認します。
2. 既知の制約で上書きが必要な場合を除き、推奨値をそのまま使います。
3. 確定する前に、最終的な **AutoScientist Config** の JSON を確認します。
4. AutoScientist にイテレーションを通じてレシピを評価・改良させます。
5. 学習後は、[結果を解釈する](/ja/autoscientist/interpreting-results)で説明しているとおり、勝率と診断指標を比較します。

## 上級者向け: API での上書きを適用する

API での上書きは、管理された実験や厳格な要件のための上級者向けの抜け道です。SDK は、学習の目的関数をトップレベルの `training_method` で、ベースモデルをトップレベルの `model` で、レシピの上書きを `hyperparams` で受け取ります。`training_type` はトップレベル引数ではなく、`hyperparams` の中のフィールドです。

上書きが必要な場合は、サポートされていないキー名を避けてください。現在のアプリ設定から有効な `hyperparams` オブジェクトをコピーするか、現在の [`create` API スキーマ](/api/python/resources/autoscientist/methods/create)から組み立て、それを `hyperparams.json` として保存して、そのまま渡します:

```python
import json
from pathlib import Path

from adaption import Adaption

client = Adaption()

dataset_id = "dataset_abc123"
hyperparams = json.loads(Path("hyperparams.json").read_text())

run = client.autoscientist.create(
    dataset_id=dataset_id,
    training_method="alignment",
    hyperparams={
        **hyperparams,
        "training_type": "lora",
        "dpo_beta": 0.1,
    },
)
print(run.id, run.status)
```

設定しなかったハイパーパラメーターのキーは、プラットフォームの管理下のままです。特定のモデルを強制するには、[サポート対象モデル](/ja/autoscientist/supported-models)を確認し、現在利用できる ID を一覧表示して、そのうち 1 つを `model` に渡します:

```python
response = client.autoscientist.list_models()
for model in response.models:
    print(model.id)
```

AutoScientist が自動的に選択・反復できるよう、`model` と `hyperparams` は設定しないままにすることをおすすめします。リクエストとステータスのワークフロー全体については、[AutoScientist を実行する](/ja/autoscientist/running-autoscientist)を参照してください。
