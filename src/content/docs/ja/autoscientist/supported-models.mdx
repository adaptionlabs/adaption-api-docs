以下のモデルはいずれも、[AutoScientist の実行を作成する](/ja/autoscientist/running-autoscientist)ときに `model` フィールドとして渡せます。実行時のモデル一覧が正となります。このページは計画のための参考資料として利用してください。

```python
response = client.autoscientist.list_models()
for model in response.models:
    print(model.id, model.api_model_size, model.methods, model.training_types)
```

現在のレスポンススキーマについては、[`autoscientist.list_models` API リファレンス](/api/python/resources/autoscientist/methods/list_models)を参照してください。

<Callout variant="note">
  モデルを選択する必要はありません。`model` を省略すると、AutoScientist が、要求された `training_method` をサポートするモデルを選択します。解決されたモデル ID は実行に含めて返されます。
</Callout>

### バッチサイズ

各モデルには有効なバッチサイズが 1 つだけあります。`batch_size` の既定値は `"max"` で、そのモデル固有の値に解決されます。**ほぼすべての実行で、変更しないのが正しい選択です。** 別の整数を指定すると、ジョブが受け付けられたあとに起動が失敗します。

より大きな実効バッチが有効な場合、モデルは勾配累積を使用します。

```python
# Recommended: let AutoScientist resolve the model and batch size.
run = client.autoscientist.create(dataset_id=dataset_id)

# Advanced: pin a model and its required batch size.
run = client.autoscientist.create(
    dataset_id=dataset_id,
    model="openai/gpt-oss-20b",
    hyperparams={"batch_size": 1},
)
```

### LoRA ランク

`lora_r` は、このページのすべてのモデルで 1 から 64 までの値を受け付けます。`lora_alpha` は `lora_r` のちょうど 1 倍または 2 倍でなければなりません。両方が同じリクエストで指定された場合、API が値を相互チェックします。

## 行数

AutoScientist は、次の有効データセットサイズの下限を適用します（ベースの行数 + 拡張分）:

| 学習方法          | 最小行数     | 対象                                |
| ----------------- | ------------ | ----------------------------------- |
| SFT (instruction) | **1,000**    | すべてのモデル                      |
| DPO (preference)  | **12,000**   | すべてのモデル                      |
| すべての方法      | **10,000**   | Gemma (≥ 26B)、Qwen (≥ 35B)、NVIDIA |

テキストのデータセットは、拡張によって下限に到達できます。マルチモーダルのデータセットは現在拡張できないため、あらかじめ十分な処理済み行数を含んでいる必要があります。AutoScientist は **20,000 行**を、起動の必須条件ではなく推奨される品質目標として扱います。

## コンテキスト長とデータ

学習コンテキストは、ファインチューニング中に使用される最大シーケンス長です。これはサービング時のコンテキストより短くなります。学習上限を超える行は、拒否されるのではなく切り詰められます。

DPO のコンテキストは SFT のコンテキストより短いことがあります。DPO 用にモデルを固定する前に、実行時の `methods` リストに `DPO` が含まれていることを確認し、上の DPO コンテキストの列を参照してください。
