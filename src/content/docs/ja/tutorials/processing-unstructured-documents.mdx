組織の知識の多くは、表形式での処理ではなく人が読むことを前提とした形式で保存されています。PDF、OCR 済みのドキュメント、スプレッドシート、ワープロファイル、スライド、メールのスレッドなどです。レイアウト、埋め込まれた表、結合セル、手書き、脚注があるため、独自の前処理は時間がかかり壊れやすくなります。

Adaptive Data アプリは、これらのファイルを生のまま受け付けます。内容を抽出して構造化し、他のデータセットと同じ列のマッピング、アダプト、評価、エクスポートのフローが使えるデータセットを生成します。

## 非構造化ドキュメントとは何ですか?

アプリは、ローカルからアップロードしても Hugging Face や Kaggle から取り込んでも、ドキュメント形式のソース資料を非構造化データとして扱います。よくある例は次のとおりです:

- **PDF**。スキャンや OCR 済みのファイルを含みます。
- 結合セル、複数行のヘッダー、シートごとに異なるレイアウトを持つ**スプレッドシート**。
- 埋め込まれた表や脚注を含む**ワープロ文書**。
- 行ではなくレイアウトによって構造が表現されている**スライド**。
- **メールのスレッド**や、同様の会話形式のエクスポート。

## アプリでドキュメントを処理する

[adaptionlabs.ai/app](https://adaptionlabs.ai/app) でサインインし、[データセットを作成](/ja/adaptive-data/create-a-dataset)して、ソースファイルをアップロードまたは取り込みます。アプリがドキュメント形式のデータを検出すると、生成される行を決める 2 つの質問が表示されます。

### ステップ 1 | 抽出を有効にする

**Yes** を選ぶと、ドキュメントを抽出して分割します。非構造化ドキュメントの処理フローを通さずにファイルを取り込みたい場合にのみ、**No** を選んでください。

![アプリが非構造化データを検出し、抽出と分割を行うかどうかを Yes と No の選択肢で尋ねています。](/unstructured-documents/extract-and-split.png)

### ステップ 2 | 分割方法を選ぶ

データセットの 1 行になる単位を選びます:

- **Per document** は、各ファイル全体を 1 行に保ちます。長いコンテキストのタスクや、ドキュメント全体からの抽出に使用します。
- **Per page** は、ページごとに 1 行を作成します。学習例を増やしたい場合や、ページ単位の内容を扱いたい場合に使用します。

進む前に、アプリが両方の選択肢について行数をプレビュー表示します。

![アプリが 2 つの分割方法を提示しています。ドキュメント全体をそれぞれ 1 行として取り込む方法と、ドキュメントの各ページをそれぞれ 1 行として取り込む方法で、それぞれの行数がプレビュー表示されています。](/unstructured-documents/split-by-document-or-page.png)

## 抽出した内容をマッピングする

分割の選択によって、適した列のマッピングパターンが見えてくることがよくあります。これらは出発点であり、制約ではありません。

### Per page | 内容をコンプリーションとして使う

各行には 1 ページ分の抽出内容が含まれます。その内容を **Completion** としてマッピングし、対応するプロンプトは Adaptive Data に生成させます。

たとえば、返品ポリシーが書かれたページをコンプリーションにすると、Adaptive Data は次のようなプロンプトを生成できます:

> Explain the conditions under which a customer can return this product.

これは、生のページからインストラクション形式のデータセットへ最も早く到達する方法です。

### Per document | 内容をコンテキストとして使う

各行にはドキュメント 1 件全体が含まれます。抽出したドキュメントを **Context** としてマッピングし、**I don't have prompt** を選択して、**Write universal prompt** を選びます。

望ましい出力を指定した、完結した指示を使用してください。例:

> Extract the customer name, effective date, renewal date, and total contract value from this document. Return valid JSON with the keys `customer_name`, `effective_date`, `renewal_date`, and `contract_value`. Use `null` when a value is not present.

アプリは、その行のドキュメントをコンテキストとして与えながら、すべての行に同じプロンプトを適用します。

## Adaptive Data に進む

両方の質問に答えると抽出が実行され、通常の Adaptive Data のデータセットが生成されます。次に進みましょう:

1. [ユニバーサルプロンプトを使った列のマッピング](/ja/adaptive-data/select-columns#ユニバーサルプロンプトを使う)。
2. [レシピとブランドコントロール](/ja/adaptive-data/configure-adaptive-data)。
3. [品質の評価](/ja/adaptive-data/evaluate-dataset-quality)。
4. アダプト済みの行の確認とエクスポート。

UI のフロー全体については、[Adaptive Data アプリのウォークスルー](/ja/tutorials/adaptive-data-app-walkthrough)に進んでください。サポートされているデータセットのワークフローを自動化するには、最新の [API リファレンス](/api/python)を使用してください。ここで説明したドキュメント抽出のオプションは、アプリで設定します。
