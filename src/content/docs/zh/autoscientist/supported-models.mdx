### 批大小

每个模型只有一个有效的批大小。`batch_size` 默认为 `"max"`，它会解析为该模型对应的取值。**对于几乎所有运行，保持该默认值不变都是正确选择。** 传入其他整数会导致任务被接受之后启动失败。

当更大的有效批次有帮助时，模型会使用梯度累积。

```python
# Recommended: let AutoScientist resolve the model and batch size.
run = client.autoscientist.create(dataset_id=dataset_id)

# Advanced: pin a model and its required batch size.
run = client.autoscientist.create(
    dataset_id=dataset_id,
    model="openai/gpt-oss-20b",
    hyperparams={"batch_size": 1},
)
```

### LoRA 秩

对于本页面上的所有模型，`lora_r` 的取值范围都是 1 到 64。`lora_alpha` 必须恰好是 `lora_r` 的一倍或两倍；当同一个请求中同时提供这两个值时，API 会交叉校验它们。

## 行数要求

AutoScientist 会强制执行以下最小有效数据集规模（基础数据行 + 数据增强）：

| 训练方法          | 最少行数     | 适用范围                            |
| ----------------- | ------------ | ----------------------------------- |
| SFT（instruction） | **1,000**    | 所有模型                            |
| DPO（preference）  | **12,000**   | 所有模型                            |
| 任意方法          | **10,000**   | Gemma (≥ 26B), Qwen (≥ 35B), NVIDIA |

文本数据集可以通过数据增强达到最低规模。多模态数据集目前无法进行增强，因此它们必须本身就包含足够多的已处理数据行。AutoScientist 把 **20,000 行**视为推荐的质量目标，而不是启动训练的硬性要求。

## 上下文长度与你的数据

训练上下文是微调期间使用的最大序列长度。它比推理服务的上下文更短。超过训练上限的数据行会被截断，而不是被拒绝。

DPO 的上下文可能比 SFT 的更短。在为 DPO 固定某个模型之前，请确认它运行时的 `methods` 列表中出现了 `DPO`，并参考上面的 DPO 上下文长度列。
