Todos los modelos siguientes pueden pasarse en el campo `model` al [crear una ejecución de AutoScientist](/es/autoscientist/running-autoscientist). La lista de modelos en tiempo de ejecución es la fuente autorizada; usa esta página como referencia de planificación.

```python
response = client.autoscientist.list_models()
for model in response.models:
    print(model.id, model.api_model_size, model.methods, model.training_types)
```

Consulta la [referencia de API de `autoscientist.list_models`](/api/python/resources/autoscientist/methods/list_models) para conocer el esquema de respuesta actual.

<Callout variant="note">
  No hace falta que selecciones un modelo. Omite `model` y AutoScientist
  elegirá uno que admita el `training_method` solicitado. El ID del modelo
  resuelto se devuelve en la ejecución.
</Callout>

### Tamaño de lote

Cada modelo tiene un único tamaño de lote válido. `batch_size` tiene el valor predeterminado `"max"`, que se resuelve a ese valor específico del modelo. **Dejarlo sin cambios es la opción correcta en casi todas las ejecuciones.** Indicar otro entero hace que el lanzamiento falle después de que el trabajo haya sido aceptado.

Los modelos usan acumulación de gradiente cuando resulta útil un lote efectivo mayor.

```python
# Recommended: let AutoScientist resolve the model and batch size.
run = client.autoscientist.create(dataset_id=dataset_id)

# Advanced: pin a model and its required batch size.
run = client.autoscientist.create(
    dataset_id=dataset_id,
    model="openai/gpt-oss-20b",
    hyperparams={"batch_size": 1},
)
```

### Rango de LoRA

`lora_r` acepta valores de 1 a 64 en todos los modelos de esta página. `lora_alpha` debe ser exactamente una o dos veces `lora_r`; la API comprueba ambos valores cuando se envían en la misma solicitud.

## Número de filas

AutoScientist exige los siguientes tamaños efectivos mínimos de conjunto de datos (filas base + aumento de datos):

| Método de entrenamiento | Filas mínimas | Se aplica a |
| ----------------------- | ------------- | ----------- |
| SFT (instrucciones) | **1.000** | Todos los modelos |
| DPO (preferencias) | **12.000** | Todos los modelos |
| Cualquier método | **10.000** | Gemma (≥ 26B), Qwen (≥ 35B), NVIDIA |

Los conjuntos de datos de texto pueden recurrir al aumento de datos para alcanzar un mínimo. Los conjuntos de datos multimodales no se pueden aumentar por ahora, así que deben contener ya suficientes filas procesadas. AutoScientist considera las **20.000 filas** un objetivo de calidad recomendado, no un requisito obligatorio para el lanzamiento.

## Longitud de contexto y tus datos

El contexto de entrenamiento es la longitud máxima de secuencia utilizada durante el ajuste fino. Es más corta que el contexto de servicio. Las filas más largas que el límite de entrenamiento se truncan en lugar de rechazarse.

El contexto de DPO puede ser más corto que el de SFT. Antes de fijar un modelo para DPO, confirma que `DPO` aparece en su lista `methods` en tiempo de ejecución y usa la columna de contexto de DPO de la tabla anterior.
