Todos os modelos abaixo podem ser passados no campo `model` ao [criar uma execução do AutoScientist](/pt/autoscientist/running-autoscientist). A lista de modelos em tempo de execução é a fonte autoritativa; use esta página como referência de planejamento.

```python
response = client.autoscientist.list_models()
for model in response.models:
    print(model.id, model.api_model_size, model.methods, model.training_types)
```

Consulte a [referência da API de `autoscientist.list_models`](/api/python/resources/autoscientist/methods/list_models) para o esquema de resposta atual.

<Callout variant="note">
  Você não precisa selecionar um modelo. Omita `model` e o AutoScientist
  selecionará um que suporte o `training_method` solicitado. O ID do modelo
  resolvido é retornado na execução.
</Callout>

### Tamanho do lote

Cada modelo tem um único tamanho de lote válido. `batch_size` usa `"max"` por padrão, que é resolvido para esse valor específico do modelo. **Deixá-lo inalterado é a escolha certa para quase toda execução.** Fornecer outro inteiro faz o lançamento falhar depois que o job é aceito.

Os modelos usam acumulação de gradiente quando um lote efetivo maior é útil.

```python
# Recommended: let AutoScientist resolve the model and batch size.
run = client.autoscientist.create(dataset_id=dataset_id)

# Advanced: pin a model and its required batch size.
run = client.autoscientist.create(
    dataset_id=dataset_id,
    model="openai/gpt-oss-20b",
    hyperparams={"batch_size": 1},
)
```

### Ordem do LoRA

`lora_r` aceita valores de 1 a 64 para todos os modelos desta página. `lora_alpha` precisa ser exatamente uma ou duas vezes `lora_r`; a API verifica os valores em conjunto quando ambos são fornecidos na mesma requisição.

## Contagem de linhas

O AutoScientist impõe os seguintes tamanhos mínimos efetivos de conjunto de dados (linhas base + aumento de dados):

| Método de treinamento | Mínimo de linhas | Aplica-se a                         |
| ----------------- | ------------ | ----------------------------------- |
| SFT (instruction) | **1.000**    | Todos os modelos                    |
| DPO (preference)  | **12.000**   | Todos os modelos                    |
| Qualquer método   | **10.000**   | Gemma (≥ 26B), Qwen (≥ 35B), NVIDIA |

Conjuntos de dados de texto podem usar o aumento de dados para atingir um mínimo. Conjuntos de dados multimodais ainda não podem ser aumentados, portanto precisam já conter linhas processadas suficientes. O AutoScientist trata **20.000 linhas** como uma meta recomendada de qualidade, não como um requisito rígido de lançamento.

## Comprimento do contexto e seus dados

O contexto de treinamento é o comprimento máximo de sequência usado durante o ajuste fino. Ele é menor que o contexto de serviço. Linhas mais longas que o limite de treinamento são truncadas, e não rejeitadas.

O contexto de DPO pode ser menor que o de SFT. Antes de fixar um modelo para DPO, confirme que `DPO` aparece na lista `methods` em tempo de execução e use a coluna de contexto de DPO acima.
