API keys authenticate **programmatic access** to Adaptive Data—the same platform capabilities you use in the app, invoked from your code, automation, or notebooks. Treat them as credentials for production integrations, not as shareable tokens.

<Callout variant="note">
  Store keys in a secret manager or environment variables. Do not commit them to source control.
</Callout>

## Create a key in the app

<Steps>
  <Step>[Sign in](https://adaptionlabs.ai/app/auth) to Adaption.</Step>
  <Step>
    Open [**Settings**](https://adaptionlabs.ai/app/settings) and the [**API keys**](https://adaptionlabs.ai/app/settings?tab=api_keys) section.
  </Step>
  <Step>
    Create a key, copy it once, and store it securely. You will not be able to view it again.
  </Step>
</Steps>

## Use the key in Python

Pass the key explicitly:

```python
from adaption import Adaption

client = Adaption(api_key="pt_live_...")
```

Or set **`ADAPTION_API_KEY`** and construct the client without arguments:

```bash
export ADAPTION_API_KEY="pt_live_..."
```

```python
from adaption import Adaption

client = Adaption()  # reads ADAPTION_API_KEY
```

The same pattern applies to **`AsyncAdaption`** for async code.

## Use the key with MCP clients

Most MCP clients sign in to Adaption with OAuth and need no key. Use a key for an MCP client that runs without a browser, such as a CI runner, by sending it as `Authorization: Bearer YOUR_ADAPTION_API_KEY`. Keys created in the app have full access, including the MCP server. See [MCP](/tools/mcp#use-an-api-key) for client configuration.

## Use the key with inference stacks

The same key calls your [inference stacks](/inference-stacks/overview) through `client.responses.create`. A key restricted to specific scopes also needs the scope of each tool a stack uses; see [API keys and scopes](/inference-stacks/call-a-stack#api-keys-and-scopes).
