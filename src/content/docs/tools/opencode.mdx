OpenCode can use Adaption's hosted models as an inference provider. Adaption serves the OpenAI Responses API, so OpenCode's compatible Responses runtime connects without a plugin. You bring an [Adaption API key](/introduction/create-api-keys) and a model ID from [Models](/inference-stacks/models).

You can also connect the [Adaption MCP server](/tools/mcp) separately to give OpenCode tools for datasets and AutoScientist runs. The two setups are independent.

## Create and export an API key

1. [Sign in](https://adaptionlabs.ai/app/auth) to Adaption.
2. Open [**Settings**](https://adaptionlabs.ai/app/settings), then [**API keys**](https://adaptionlabs.ai/app/settings?tab=api_keys).
3. Create a key and copy it. You will not be able to view the key again.
4. Export it as `ADAPTION_API_KEY` so OpenCode can read it automatically:

   ```bash
   export ADAPTION_API_KEY="pt_live_..."
   ```

Do not commit a configuration file containing a real key.

## Add the provider

OpenCode reads project configuration from `opencode.json(c)` or `.opencode/opencode.json(c)` in the current directory, and global configuration from `~/.config/opencode/opencode.json(c)`. Use the global file to make Adaption available in every project.

Adaption's inference endpoint implements the Responses API, so the provider uses the compatible Responses runtime package:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "adaption": {
      "name": "Adaption",
      "env": ["ADAPTION_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible/responses",
      "settings": {
        "baseURL": "https://api.prod.adaptionlabs.ai/api/v1",
      },
      "models": {
        "qwen3.5-397b": {
          "name": "Qwen 3.5 397B",
        },
        "glm-5.2": {
          "name": "GLM 5.2",
        },
        "deepseek-v4-flash": {
          "name": "DeepSeek V4 Flash",
        },
        "gemma-4-31b-it": {
          "name": "Gemma 4 31B IT",
        },
        "qwen3.8-27b": {
          "name": "Qwen 3.8 27B",
        },
      },
    },
  },
}
```

`env` tells OpenCode to send `ADAPTION_API_KEY` as `Authorization: Bearer ...` on every request. API keys are bound to an organization, so no `X-Organization-Id` header is needed. Add or remove entries in `models` to match what your key can access; see [Models](/inference-stacks/models) for the full list.

Config changes apply without a restart. OpenCode watches the file and reloads providers after a save.

## Select a model

In the TUI, run `/models` and choose an `adaption/...` entry. To set a default instead, set the top-level `model` field:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "adaption/qwen3.5-397b",
  "providers": {
    "adaption": {
      "env": ["ADAPTION_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible/responses",
      "settings": {
        "baseURL": "https://api.prod.adaptionlabs.ai/api/v1",
      },
      "models": {
        "qwen3.5-397b": { "name": "Qwen 3.5 397B" },
      },
    },
  },
}
```

Then ask OpenCode:

> Write a one-sentence bedtime story about a unicorn.

The response comes from the Adaption Responses API. Streaming works the same way it does for any OpenCode model.

## Use an inference stack

An inference stack is a saved configuration of a model, tools, datasets, and memory. Pass its slug as `stack:<slug>` through the same provider.

Stacks belong to your account and cannot be auto-discovered, so add one as a model entry whose `modelID` points at the stack:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "adaption": {
      "env": ["ADAPTION_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible/responses",
      "settings": {
        "baseURL": "https://api.prod.adaptionlabs.ai/api/v1",
      },
      "models": {
        "support-assistant": {
          "name": "Support Assistant Stack",
          "modelID": "stack:support-assistant",
        },
      },
    },
  },
}
```

Select `adaption/support-assistant` in `/models`, or set `"model": "adaption/support-assistant"`. See [Key concepts](/inference-stacks/key-concepts) for how a stack's model, tools, datasets, and memory apply to each request.

## Optional: connect the MCP server

To let OpenCode call Adaption's dataset and AutoScientist tools, add the hosted MCP server as well. The CLI preserves unrelated configuration:

```sh
opencode mcp add adaption --global --url https://api.prod.adaptionlabs.ai/api/v1/mcp
```

Then run `/mcps`, select the `adaption` server, and sign in with your Adaption account in the browser. No API key is needed for the MCP connection.

See [MCP](/tools/mcp) for the complete tool catalog. The MCP server is separate from the inference provider and does not affect model selection.

## Troubleshooting

- **`Model unavailable: adaption/...`** — The model ID in the `models` map is not what your key grants, or `modelID` does not match a hosted model or `stack:<slug>`. Confirm the ID against [Models](/inference-stacks/models) or your inference stacks page.
- **Requests fail with `401` or `missing required scope(s)`.** `ADAPTION_API_KEY` is unset in the OpenCode server's environment, or the key was created with a scope list that lacks `adaption-mcp:read` or `adaption-mcp:write`. See [Authentication and permissions](/tools/mcp#authentication-and-permissions).
- **The wrong organization's data or stacks appear.** API keys are bound to one organization. Reissue a key in the organization you want and update `ADAPTION_API_KEY`.
- **A request returns `502` or `503`.** The model provider could not complete the request, or inference is not configured for this environment. Wait and retry; if it persists, check the model's status in the Adaption app.
